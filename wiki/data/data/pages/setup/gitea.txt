====== Gitea — Self-Hosted Git ======

**Prerequisite:** [[setup:traefik|Traefik & dnsmasq]] running.

----

===== What Gitea Provides =====

Gitea is a lightweight, self-hosted Git service. This deployment gives you:

  * A web UI at ''http:%%//%%gitea.local'' for browsing repositories, issues, and pull requests.
  * SSH-based ''git clone / push / pull'' via ''ssh:%%//%%git@192.168.56.3:2222''.
  * A Postgres 16 database for durable storage of users, repositories, and metadata.

----

===== File Overview =====

<code>
gitea/
├── docker-compose.yml
├── .env.example          # Copy to .env
├── data/                 # Gitea runtime data (created at startup)
└── db/                   # Postgres data directory (created at startup)
</code>

----

===== docker-compose.yml Explained =====

<code>
services:
  gitea:
    image: gitea/gitea:1.22.3
    environment:
      - GITEA__database__DB_TYPE=postgres
      - GITEA__database__HOST=gitea-db:5432
      - GITEA__database__NAME=${DB_NAME}
      - GITEA__database__USER=${DB_USER}
      - GITEA__database__PASSWD=${DB_PASSWORD}
    depends_on:
      gitea-db:
        condition: service_healthy   # waits until Postgres is ready
    networks:
      - proxy     # visible to Traefik
      - internal  # can reach gitea-db
    ports:
      - "2222:22" # SSH on non-standard host port

  gitea-db:
    image: postgres:16-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $POSTGRES_USER -d $POSTGRES_DB"]
      interval: 10s
      retries: 5
    networks:
      - internal  # isolated — not reachable from host or Traefik
</code>

**Design decisions:**
  * ''depends_on: condition: service_healthy'' prevents Gitea from starting before Postgres is accepting connections, eliminating race-condition startup failures.
  * ''gitea-db'' is on ''internal'' only — it is not reachable from outside the Docker network.
  * SSH is exposed on port 2222 to avoid conflicting with the VM's own SSH daemon on port 22.

===== Step-by-Step Deployment =====

==== Step 1: Prepare .env ====

<code>
cp gitea/.env.example gitea/.env
nano gitea/.env
</code>

Set these values:

<code>
DB_NAME=gitea
DB_USER=gitea
DB_PASSWORD=changeme_use_a_strong_password
</code>

==== Step 2: Start the stack ====

<code>
docker compose -f gitea/docker-compose.yml up -d
</code>

Docker Compose will start ''gitea-db'' first, wait for its healthcheck to pass, then start ''gitea''.

==== Step 3: Verify containers ====

<code>
docker compose -f gitea/docker-compose.yml ps
</code>

Both containers should show ''Up''; ''gitea-db'' should show ''(healthy)''.

==== Step 4: Complete the web installer ====

  - Open ''http:%%//%%gitea.local'' in a browser.
  - The first-run installer appears — most fields are pre-filled from environment variables.
  - Confirm:
    - **Database type**: PostgreSQL
    - **Host**: ''gitea-db:5432''
    - **Database name / user / password**: as set in ''.env''
  - Set the **Administrator account** username and password at the bottom.
  - Click **Install Gitea**.

==== Step 5: Test SSH ====

Add your public key first: Gitea → User Settings → SSH / GPG Keys → Add Key.

Then test from the host machine:

<code>
ssh -T git@192.168.56.3 -p 2222
</code>

Expected response: ''Hi USERNAME! You've successfully authenticated...''

==== Step 6: Create a repository ====

  - Log in at ''http:%%//%%gitea.local''.
  - Click **+** → **New Repository**.
  - Clone via SSH (replace ''USERNAME'' and ''REPONAME''):

<code>
git clone ssh://git@192.168.56.3:2222/USERNAME/REPONAME.git
</code>

----

===== Updating Gitea =====

Change the image tag in ''docker-compose.yml'' (e.g. ''1.22.3'' → ''1.23.0''), then:

<code>
docker compose -f gitea/docker-compose.yml pull
docker compose -f gitea/docker-compose.yml up -d
</code>

Gitea runs database migrations automatically on startup.

----

===== Troubleshooting =====

^ Symptom ^ Likely Cause ^ Fix ^
| ''http:%%//%%gitea.local'' not loading | Traefik not running or gitea container down | Check ''docker ps'', start traefik first |
| Installer shows DB connection error | Wrong credentials in ''.env'' | Stop stack, fix ''.env'', ''docker compose up -d'' |
| SSH returns "connection refused" | Port 2222 not mapped | Confirm ''ports: - "2222:22"'' in compose file |
| gitea-db stuck in "starting" | Healthcheck command wrong | Check ''docker logs gitea-db'' |
